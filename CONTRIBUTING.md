# Как добавить инструмент

`README.md` и всё в `catalog/` — **сгенерированные файлы**. Пулреквест, который правит их
напрямую, не пройдёт CI: изменения затрутся при следующей сборке. Править нужно YAML.

## Быстрый путь — без возни с YAML

[Заведи issue по шаблону](https://github.com/ai2bteam/ai-content-stack/issues/new?template=add-tool.yml).
Достаточно ссылки и одного предложения о том, зачем этот инструмент брать.

## Обычный путь

1. Добавь запись в `data/tools.yaml`. Поля описаны в [data/schema.md](data/schema.md).
2. Если инструмент закрывает задачу, которой ещё нет в таблице маршрутизации —
   допиши строку в `data/routing.yaml`.
3. Пересобери и проверь:

```bash
pip install pyyaml
python3 scripts/build.py
python3 scripts/check_links.py
```

4. Закоммить и YAML, и сгенерированные файлы — CI сверяет, что они не разошлись.

## Что делает запись хорошей

**`tagline` — это не определение, а довод.** Сравни:

> ❌ «Библиотека для анимации на JavaScript.»
> ✅ «Бывший Framer Motion. Гибридный движок вывозит 120fps, мини-версия `animate()` весит 2.3kb.»

Первое не помогает выбрать. Второе — помогает.

**Пиши, чем инструмент отличается от соседа по таблице.** Каталог полезен ровно настолько,
насколько помогает выбрать между двумя похожими вариантами. Если у инструмента есть
неочевидный лимит, подводный камень или условие лицензии — это в `note`.

**`status: verified` ставится только после реального использования.** Не «выглядит рабочим»,
не «звёзд много», а «гоняли на проекте». Вся ценность ⭐ в том, что ей можно верить.

**Не тащи в репозиторий ключи.** В `env` идут только имена переменных окружения.
Значения живут в конфиге агента, и им место там.

## Что в каталог не берём

- Инструменты, которые уже не поддерживаются или чей сайт лежит.
- Реферальные ссылки и обёртки, добавляющие наценку к чужому API.
- «Ещё один агрегатор моделей» без объяснения, зачем он при уже перечисленных.
