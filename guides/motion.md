# Motion: анимация в вебе

**[motion.dev](https://motion.dev/)** · React, JavaScript, Vue · open source

Бывший Framer Motion. Переименовался, когда перестал быть только React-библиотекой:
сейчас это три параллельных API — для React, для ванильного JS и для Vue.

## Почему он, а не GSAP

Движок гибридный: часть работы отдаётся нативным браузерным API вместо того, чтобы
крутить каждый кадр в JavaScript. Отсюда 120fps с GPU-ускорением и очень маленький вес —
мини-версия `animate()` для HTML и SVG занимает 2.3kb, а API в среднем заметно
компактнее, чем у GSAP на тех же задачах.

Из коробки идёт всё, что обычно приходится дописывать руками: пружинная физика, жесты
(drag, tap, hover), layout- и shared-layout-переходы, анимация появления и исчезновения
элементов, скролл-связанные эффекты, таймлайны.

Практический выбор простой: **Motion** — если нужны интерфейсные анимации, переходы
между состояниями и реакция на действия пользователя. **GSAP** — если нужна сложная
хореография по таймлайну и морфинг SVG.

## Что берём

Микровзаимодействия, анимированные списки, переходы между страницами, состояния
загрузки, сложные последовательности. Всё это — про интерфейс, который кто-то смотрит
вживую в браузере.

## Чего не делаем: Motion и Remotion

**Внутри Remotion-композиции Motion не используется.** Это не вкусовщина, а следствие
архитектуры.

Motion анимирует по часам реального времени: браузер отдаёт `requestAnimationFrame`,
библиотека считает, сколько прошло миллисекунд, и обновляет свойства. Remotion рендерит
покадрово — он подставляет номер кадра и ожидает, что содержимое кадра является чистой
функцией от этого номера. Реального времени в этот момент не существует: рендер одного
кадра может занять секунду, а следующего — десять.

Поставь Motion в Remotion-сцену, и в превью всё будет двигаться, а в отрендеренном
файле анимация окажется застывшей или рваной — рендерер просто не дождался того момента,
который библиотека собиралась показать.

В Remotion движение задаётся через `useCurrentFrame()` и `interpolate()` либо `spring()`.
Тот же результат, но время идёт по кадрам.

```tsx
// Remotion: движение — функция от номера кадра
const frame = useCurrentFrame();
const opacity = interpolate(frame, [0, 30], [0, 1], {
  extrapolateRight: "clamp",
});
```

Где Motion в видео-пайплайне всё же уместен: в HTML- или Canvas-сценах, которые потом
записываются с экрана через [Playwright](../catalog/assembly.md). Там анимация реально
проигрывается в браузере в реальном времени, и всё честно.
